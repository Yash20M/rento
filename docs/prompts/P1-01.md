# P1-01 — Monorepo scaffold

## 1. Role
You are a senior DevOps/TypeScript tooling engineer on the Rento platform.

## 2. Context
- Product: time-based rental of individually-tracked physical assets from nearby drawers.
- Architecture in play: repository tooling only — pnpm workspace, shared TypeScript/ESLint/Prettier config. No application code.
- Relevant README sections:
  - §12.1 Monorepo layout — exact directory targets (`apps/api`, `apps/admin`, `packages/contracts`, `packages/config`, `pnpm-workspace.yaml`).
  - §5 Final recommended stack — Node LTS, TypeScript, pnpm workspaces; Flutter lives in the same repo but is **not** a pnpm package.
  - §12.3 Configuration — `.env` never committed; `.env.example` is.
- Existing code to read first: none — greenfield (repo currently holds only `README.md`, `DEVELOPMENT_PLAN.md`, `AGENTS.md`, `CLAUDE.md`). Those markdown files are hand-formatted and must not be rewritten by tooling.
- Decisions already made (do not revisit): pnpm workspaces; NestJS API, React+Vite admin, Flutter mobile (scaffolded in later tasks); Windows 11 developer machine, so scripts are Node/pnpm only; line endings LF.
- Toolchain on the machine: Node v22.13.1, pnpm 10.24.0, git 2.47.1, Docker 28.3.2. Flutter is **not** on PATH (not needed here; P1-08).

## 3. Goal
A clean clone can run `pnpm install && pnpm lint && pnpm typecheck` on the empty workspace and get green, and a deliberately bad source file makes `pnpm lint` fail. The repo is a local git repository with sane ignores. Later tasks (P1-03, P1-10, P1-07…) drop their code into the existing package shells.

## 4. Scope
**In scope**
- `git init` (local only, default branch `main`), `.gitignore`, `.gitattributes`, `.editorconfig`.
- Root `package.json` (private, `packageManager`, `engines`), `pnpm-workspace.yaml`, `.nvmrc`.
- `packages/config` (`@rento/config`): shared `tsconfig.base.json`, ESLint flat config export, Prettier config.
- Package shells with `package.json`, `tsconfig.json`, `src/index.ts`: `apps/api` (`@rento/api`), `apps/admin` (`@rento/admin`), `packages/contracts` (`@rento/contracts`).
- Root scripts: `lint`, `lint:fix`, `format`, `typecheck`, `verify`.
- `.env.example` at root documenting local DB variables only.

**Out of scope**
- NestJS / Vite / React code → P1-03, P1-10.
- Docker Compose and DB init → P1-02.
- Test runners (Vitest, Jest, Playwright) → P1-03/P1-05/P1-10.
- CI workflow and a real `verify` aggregate → P1-11 (here `verify` = lint + typecheck only).
- `apps/mobile` Flutter project → P1-08.
- Adding a git remote or pushing → needs user confirmation; **not done here**.
- `packages/contracts` OpenAPI/client generation → P1-07.

## 5. Detailed requirements
1. `git init -b main` in the repo root; **no remote is added**. No commit is made (user commits on request).
2. `.gitignore` excludes: `node_modules/`, `dist/`, `build/`, `coverage/`, `.env`, `.env.*` (except `.env.example`), `*.log`, `.DS_Store`, `.vscode/*` except shared settings (none created), `*.tsbuildinfo`, `playwright-report/`, `test-results/`, Flutter build artefacts (`apps/mobile/build/`, `.dart_tool/`), `.claude/settings.local.json`.
3. `.gitattributes`: `* text=auto eol=lf`.
4. `.editorconfig`: UTF-8, LF, final newline, 2-space indent, trim trailing whitespace (except `*.md`).
5. Root `package.json`: `"private": true`, `"packageManager": "pnpm@10.24.0"`, `"engines": {"node": ">=22"}`; devDependencies hold ESLint, typescript-eslint, Prettier, TypeScript (single versions for the whole repo).
6. `pnpm-workspace.yaml` lists `apps/api`, `apps/admin`, `packages/*`; `apps/mobile` is **not** listed.
7. `@rento/config` exports: `tsconfig.base.json` (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `isolatedModules`, `esModuleInterop`, `skipLibCheck`, target `ES2022`, `moduleResolution` `Bundler`/`NodeNext` as appropriate), `eslint.js` (flat config array; `typescript-eslint` recommended-type-checked-compatible rules, `no-console` as `warn` is NOT allowed — warnings count as failures: lint runs with `--max-warnings 0`), `prettier.js` (semi, single quotes, trailing commas `all`, print width 100, `endOfLine: lf`).
8. Each package shell extends `@rento/config/tsconfig.base.json`, has `typecheck` script `tsc --noEmit`, and an `src/index.ts` containing `export {};`.
9. Root `eslint.config.mjs` imports the shared config; ignores `**/dist`, `**/node_modules`, `apps/mobile`, `**/*.md`.
10. Root `.prettierignore` ignores `*.md`, `pnpm-lock.yaml`, `apps/mobile`, `dist`, `node_modules` (README/DEVELOPMENT_PLAN are hand-formatted and must remain untouched).
11. Root scripts: `lint` = `eslint . --max-warnings 0 && prettier --check .`; `lint:fix`; `format` = `prettier --write .`; `typecheck` = `pnpm -r --if-present typecheck`; `verify` = `pnpm lint && pnpm typecheck`.
12. `.env.example` documents `DATABASE_URL` (local PostGIS URL placeholder) and `NODE_ENV`; contains no real secrets.
13. `pnpm-lock.yaml` is generated and kept (committed later by the user).

## 6. Files to create / modify
Create: `.gitignore`, `.gitattributes`, `.editorconfig`, `.nvmrc`, `.prettierignore`, `.env.example`, `package.json`, `pnpm-workspace.yaml`, `eslint.config.mjs`, `prettier.config.mjs`, `packages/config/{package.json,tsconfig.base.json,eslint.js,prettier.js}`, `packages/contracts/{package.json,tsconfig.json,src/index.ts}`, `apps/api/{package.json,tsconfig.json,src/index.ts}`, `apps/admin/{package.json,tsconfig.json,src/index.ts}`, `pnpm-lock.yaml` (generated).
Modify: `DEVELOPMENT_PLAN.md` (status, Evidence, dashboard, Progress log).

## 7. Acceptance criteria
- [ ] AC-1 `pnpm install` succeeds from a clean state (no `node_modules`). → T-01
- [ ] AC-2 `pnpm lint` passes on the empty workspace with zero warnings. → T-02
- [ ] AC-3 `pnpm typecheck` runs `tsc --noEmit` in all three TS packages and passes. → T-03
- [ ] AC-4 A deliberately bad file (unused variable / `debugger` / bad formatting) makes `pnpm lint` exit non-zero; removing it restores green. → T-04, T-05
- [ ] AC-5 A deliberate type error makes `pnpm typecheck` exit non-zero; removing it restores green. → T-06
- [ ] AC-6 `.env` files are ignored, `.env.example` is not; `node_modules` ignored. → T-07
- [ ] AC-7 `README.md` and `DEVELOPMENT_PLAN.md` are not modified by `pnpm lint:fix`/`format`. → T-08
- [ ] AC-8 `git status` shows a repo on `main` with no remote configured. → T-09

## 9. Commands to run (gates)
Raw equivalents — the gates are what this task *creates*: `pnpm install` · `pnpm lint` · `pnpm typecheck` · `pnpm verify`. (Say so in Evidence.)

## 10. Definition of done
All acceptance criteria met · T-01…T-09 executed with recorded results · bad files removed and tree green · no lint rules disabled · Evidence recorded in DEVELOPMENT_PLAN.md · box ticked · Progress log line added · dashboard refreshed.

## 11. Stop conditions
Stop and ask the user if: a remote repo URL is needed, `pnpm install` cannot reach the registry, or any requirement here conflicts with the README.
