# P1-10 — Admin SPA scaffold

## 1. Role
You are a senior frontend engineer (React, TypeScript, Vite, Tailwind/shadcn, Testing Library, Playwright) on the Rento platform.

## 2. Context
- Product: time-based rental platform. The admin panel is an internal, logged-in tool (no SEO/SSR) used by staff to manage inventory, drawers, bookings, roles and audit (README §13).
- Architecture in play: `apps/admin` only — a static SPA that talks to the same NestJS API (`/v1/admin/*`, later) through the generated typed client in `packages/contracts`. Authorization is server-side; the UI is UX only (README §13.2, §13.5).
- Relevant README sections: §4.5 (React+TS+Vite SPA; TanStack Query; React Router or TanStack Router; shadcn/ui), §13.1 (folder structure: `app/`, `api/`, `features/`, `components/`), §13.2 (access token in memory, refresh cookie — implemented in P3-01), §14.1 (RFC 9457 errors), plan §6 (Vitest + Testing Library; Playwright for e2e).
- Existing code to read first: `apps/admin/{package.json,tsconfig.json,src/index.ts}`, `packages/contracts/src/index.ts`, `packages/config/{eslint.js,tsconfig.base.json}`, root `package.json`, `.prettierignore`.
- Decisions already made (do not revisit): Vite + React 19 + TypeScript; **React Router** (data router) for routing; TanStack Query for server state; shadcn/ui (Radix + Tailwind CSS v4) as copy-in components; generated client from `@rento/contracts`; Zod for env validation.
- Out-of-scope neighbours: login behaviour, token handling, route guards, `/admin/me` bootstrap → **P3-01**; permission-aware UI → **P3-02**; any feature page (roles, inventory, drawers, bookings …) → P3-03…; CORS/CSP/headers → P4 security hardening; CI wiring → P1-11.

## 3. Goal
`pnpm --filter admin dev` serves a styled admin shell; `pnpm --filter admin build` produces a static bundle; the shell shows live API status from the typed client; `/login` renders a (non-functional) sign-in form; unknown URLs render a 404 page. Component tests and a Playwright smoke test prove it.

## 4. Scope
**In scope**
- Vite + React + TS app, Tailwind v4 + shadcn base (theme tokens, `cn()` helper, `Button`, `Input`, `Label`, `Card`), alias `@/` → `src/`.
- `src/config/env.ts`: validated Vite env (`VITE_API_BASE_URL`, default `''` = same origin; dev proxy for `/v1`, `/healthz`, `/readyz` → `API_PROXY_TARGET`, default `http://127.0.0.1:3000`).
- `src/api/`: `client.ts` (`createApiClient(env.apiBaseUrl)` singleton factory), `ApiProvider`/`useApi()` (injectable client for tests), `useApiHealth()` TanStack Query hook.
- `src/app/`: providers (QueryClient, Api), router (`/` shell, `/login`, `*`), `AppLayout` (sidebar placeholder nav + header + API status badge).
- Pages: `features/home/HomePage`, `features/auth/LoginPage` (placeholder form, submit disabled with "Sign-in arrives in P3-01" note), `components/NotFoundPage`.
- Vitest + Testing Library + jest-dom (jsdom); Playwright config + smoke test; ESLint React-hooks rules; scripts.
- `apps/admin/.env.example`.

**Out of scope**: see §2. No auth, no real data, no feature pages, no icons beyond a couple of lucide icons.

## 5. Detailed requirements
1. **Scripts** (`apps/admin/package.json`): `dev` (vite), `build` (`tsc --noEmit && vite build`), `preview`, `typecheck` (`tsc --noEmit`), `test` (`vitest run`), `test:e2e` (`playwright test`). Package stays `"type": "module"`.
2. **Env** (`parseEnv(raw)`): `VITE_API_BASE_URL` optional; if set it must be an `http(s)` URL without trailing slash normalised away; invalid ⇒ throws `EnvError` naming the key (never echoes other values). `env` is parsed once from `import.meta.env`; app fails fast at startup with a readable full-page error if invalid.
3. **Client**: `useApi()` returns the `ApiClient` from `@rento/contracts`; `ApiProvider` accepts a `client` prop (tests inject a stub-`fetch` client); default client uses `env.apiBaseUrl`.
4. **`useApiHealth()`**: query key `['api','health']`, calls `GET /healthz`; refetch every 30 s; `retry: 1`; returns `{ status: 'ok' | 'down' | 'checking' }` derived from the query (network error or non-2xx ⇒ `down`).
5. **Layout**: header "Rento Admin", left nav with disabled placeholder entries (Dashboard active; Inventory, Drawers, Bookings, Roles, Audit shown disabled with title "Coming in a later task"), main `<Outlet/>`, API status badge with accessible text (`API: ok | down | checking`).
6. **Routes**: `/` → layout + `HomePage` (welcome card + API status card); `/login` → standalone `LoginPage` (email, password, submit disabled) outside the layout; any other path → `NotFoundPage` (heading "Page not found", link to `/`). Document `<title>`: "Rento Admin".
7. **Accessibility**: form controls have labels; landmarks `header`, `nav`, `main`; focus-visible styles from shadcn tokens.
8. **Quality**: no secrets in the bundle; `.env.example` lists `VITE_API_BASE_URL` and `API_PROXY_TARGET` with comments; ESLint (`react-hooks` recommended) passes with `--max-warnings 0`; strict TS passes.
9. **Playwright**: config starts `vite preview` on a fixed port after a build; Chromium only; smoke test navigates to `/login` and asserts heading, labelled email/password fields, disabled submit; a second test stubs `**/healthz` via `page.route` to assert the shell shows "API: ok" and then "API: down" when the stub returns 503.
