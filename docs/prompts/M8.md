# M8 — Aadhaar identity verification (fast track: P2-37, P2-38, P3-32, P3-33)

Owner decision (2026-10-18, answers README Q-11): **every customer must verify their identity with an Aadhaar card before they can book.** The real verification vendor is integrated later (P4-16); until then a fake verifier stands behind the same interface.

## Decisions (engineering defaults — flagged)
- **Privacy first.** The full number is validated (12 digits, first digit 2–9, Verhoeff check digit — catches every single-digit typo and adjacent swap), sent once to the verifier and DISCARDED. Stored: the last four digits (to show `XXXX XXXX 1234`) and an HMAC-SHA256 of the number keyed with a server-derived secret (so one card cannot verify two accounts, yet the number cannot be recovered from the database). Never in logs, audit rows, API answers or the app's memory after the OTP step.
- **Flow**: `POST /v1/me/kyc/aadhaar` → OTP sent to the phone linked to the card (request valid 10 min, at most 5 starts per 24 h) → `POST /v1/me/kyc/aadhaar/verify` (5 wrong codes lock the request) → `verified`. One verified account per card (`409 AADHAAR_IN_USE`, enforced by a partial unique index as well as a check). A customer declined by staff cannot retry on their own (`409 INVALID_STATE`) until staff reset it.
- **Gate**: `POST /v1/bookings` answers `403 KYC_REQUIRED` for anyone not verified (`KYC_REQUIRED` env, on by default; tests switch it off except the KYC suite). Existing holds/bookings are unaffected; extension and payment of an existing hold are not gated.
- **Fake verifier**: accepts one fixed code (`KYC_FAKE_OTP`, default `123456`) — development and demos only.
- **Staff** (`users:read` / `users:write`, unrestricted grants only — customers are not tied to a drawer): list (search, identity filter, cursor), detail (state, masked number, bookings), `approve` / `reject` / `reset` with a mandatory reason, audited in the same transaction.
- **App**: verification screen (consent text, number grouped in fours, OTP step, plain-language errors), account-tab tile, "Verify now" from a refused reservation. **Admin**: Customers screen with the same decisions.
- New codes `KYC_REQUIRED` (403), `AADHAAR_IN_USE` (409); migration `0011_kyc`.

## Tests
Unit: Verhoeff (published vectors, every single-digit typo, adjacent swaps, shape rules). API (`m8-kyc.api.spec`, 18): gate, flow, privacy assertions (SQL dump, responses, log lines contain no number), invalid numbers, one-card-one-account incl. the race, OTP lockout/expiry/ownership, daily limit, staff permission matrix, list/filter/paging, decisions + audit. Flutter: formatter, flow, wrong code, each refusal, gate → "Verify now". Admin: list, permissions, filters, detail, decisions. Mutations: gate removed (3 tests fail), gate weakened to "not rejected" (K-1 fails).
