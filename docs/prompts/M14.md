# M14 — Cross-role journey test and owner admin account (fast track: P3-25 part, P3-26 part)

Owner request (2026-10-18): "next, and also give me an admin email and password and store them in env".

## Decisions (engineering defaults — flagged)

- **Owner admin account**: `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME` live in the repository's untracked `.env` (gitignored; `.env.example` documents the keys with empty values). The demo seed (`apps/api/scripts/seed-demo.mjs`) reads them, creates or signs in that account and makes it Super Admin (the one SQL step the API deliberately cannot do). The password is random and strong (policy: ≥ 10 characters, not common), never committed, never printed by the seed. For LOCAL development databases only; production's first Super Admin still comes from the server-side CLI (one-time setup link).
- **Journey test** (`m14-journey.api.spec`): one story through the public HTTP contract only, in the order a real day happens, with the same session mechanics the apps use (admin: HttpOnly cookie session + silent refresh; customer: bearer tokens renewed after clock jumps). It is the API-level counterpart of the browser smoke (`pnpm demo:smoke`), and it runs in CI.

## The story (J-1…J-11)

Owner signs in (cookie) and survives a reload → sets up a drawer with two units and uploads the product photo → new customer is stopped by the identity gate, then verifies with Aadhaar → sees the photo, holds a slot and pays → admin list, dashboard, schedule, customers and payments all show it → owner moves the booking to the other unit (customer sees no change) → hand-over, extension paid in the app, return → reports add up (booking, hours, money = rental + deposit + extension) and the audit trail names the actions → second booking cancelled with a full refund visible in the ledger → owner suspends and reinstates the customer → admin sign-out ends the browser session for good.
