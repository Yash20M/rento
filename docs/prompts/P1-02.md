# P1-02 — Local stack with Docker Compose

## 1. Role
You are a senior DevOps/backend engineer on the Rento platform.

## 2. Context
- Product: time-based rental of individually-tracked physical assets from nearby drawers.
- Architecture in play: local development infrastructure only (PostgreSQL+PostGIS, Mailpit mail catcher). The `api` and `admin` containers named in README §17.1 arrive with P1-03 / P1-10 and are **not** added here.
- Relevant README sections:
  - §17.1 Environments — local = `docker compose up` with PostGIS + Mailpit.
  - §12.1 Layout — `infra/compose.yaml`, `infra/db/` init scripts.
  - §9.2 Schema — requires extensions `postgis`, `btree_gist` (exclusion constraint on `tstzrange`), `pgcrypto`.
  - §5 Stack — PostgreSQL 16 + PostGIS.
- Existing code to read first: root `package.json`, `.env.example`, `eslint.config.mjs`, `packages/config/eslint.js` (from P1-01).
- Decisions already made (do not revisit): image `postgis/postgis:16-3.4` (already on the dev machine; the version the README prototype was tested on); no Redis; Node/pnpm scripts only (Windows 11 dev machine, Git Bash available).
- Environment fact: host port **5432 is occupied** by an unrelated container (`medpet-postgres`) — do not stop it. Rento's local DB is published on host port **5433**.

## 3. Goal
`pnpm dev:db` brings up a healthy PostGIS 16 database (extensions `postgis`, `btree_gist`, `pgcrypto` installed) and Mailpit; `pnpm dev:down` stops them; `pnpm check:stack` proves it with assertions and exits non-zero on any failure.

## 4. Scope
**In scope**
- `infra/compose.yaml` with services `db` and `mailpit`, named volume for DB data, healthchecks, ports bound to `127.0.0.1` only.
- `infra/db/init/01-extensions.sql` enabling the three extensions.
- Root scripts `dev:db`, `dev:down`, `check:stack`.
- `infra/scripts/check-stack.mjs` (Node, cross-platform) that asserts the stack state.
- `.env.example` updated: `DATABASE_URL` uses port 5433; add `SMTP_HOST`, `SMTP_PORT`.
- ESLint node globals for `*.mjs`/`*.js` scripts (the lint gate must stay green).

**Out of scope**
- Migrations / schema → P1-04. API and admin containers → P1-03 / P1-10. Seed data → later tasks. Dockerfiles → P4. `dev:reset` (volume deletion is destructive; not added without request).

## 5. Detailed requirements
1. Compose project name `rento`. `db`: image `postgis/postgis:16-3.4`; env `POSTGRES_USER=rento`, `POSTGRES_PASSWORD=rento`, `POSTGRES_DB=rento` (local-dev-only credentials, documented as such); port `127.0.0.1:5433:5432`; volume `rento_pgdata:/var/lib/postgresql/data`; `./db/init` mounted read-only at `/docker-entrypoint-initdb.d`; healthcheck `pg_isready -U rento -d rento`.
2. `mailpit`: image `axllent/mailpit` pinned to a specific version tag (not `latest`); ports `127.0.0.1:1025:1025` (SMTP) and `127.0.0.1:8025:8025` (UI/API); healthcheck via `/mailpit readyz`.
3. `01-extensions.sql`: `CREATE EXTENSION IF NOT EXISTS postgis; … btree_gist; … pgcrypto;`. Note in a comment that init scripts only run on a fresh data volume.
4. `pnpm dev:db` = `docker compose -f infra/compose.yaml up -d --wait` (returns only when healthchecks pass). `pnpm dev:down` = `docker compose -f infra/compose.yaml down` (keeps the volume).
5. `check-stack.mjs` asserts, exiting 1 with a clear message on the first failure:
   a. `db` and `mailpit` services report `healthy`;
   b. `SELECT extname FROM pg_extension` (via `docker compose exec -T db psql …`) contains `postgis`, `btree_gist`, `pgcrypto`;
   c. a sanity query `SELECT ST_AsText(ST_MakePoint(77.5946, 12.9716))` returns `POINT(77.5946 12.9716)` (longitude first);
   d. Mailpit API `GET http://127.0.0.1:8025/api/v1/info` returns 200.
6. The script must not print or require secrets beyond the documented local credentials, and must not modify data.
7. Lint stays green with `--max-warnings 0`: add `globals.node` for `**/*.{js,mjs}` in `packages/config/eslint.js` (no rules disabled).

## 6. Files to create / modify
Create: `infra/compose.yaml`, `infra/db/init/01-extensions.sql`, `infra/scripts/check-stack.mjs`.
Modify: `package.json` (scripts), `.env.example`, `packages/config/eslint.js` + `packages/config/package.json` (`globals` dep), `DEVELOPMENT_PLAN.md`.

## 7. Acceptance criteria
- [ ] AC-1 `pnpm dev:db` returns exit 0 with both services healthy. → T-01
- [ ] AC-2 Extensions `postgis`, `btree_gist`, `pgcrypto` exist. → T-02
- [ ] AC-3 `ST_MakePoint(lng, lat)` ordering confirmed. → T-03
- [ ] AC-4 Mailpit API reachable on 8025; SMTP port 1025 accepts connections. → T-04
- [ ] AC-5 Ports are bound to loopback only; the unrelated `medpet-postgres` is untouched. → T-05
- [ ] AC-6 `pnpm check:stack` fails (non-zero) when the stack is down. → T-06
- [ ] AC-7 `pnpm dev:down` stops containers; data volume survives and a second `dev:db` is healthy. → T-07
- [ ] AC-8 `pnpm verify` still green. → T-08

## 9. Commands to run (gates)
`pnpm dev:db` · `pnpm check:stack` · `pnpm dev:down` · `pnpm verify` (raw docker commands used for T-05; say so in Evidence).

## 10. Definition of done
All ACs met · T-01…T-08 executed with recorded results · lint/typecheck green · stack left stopped or running (state it) · Evidence recorded · box ticked · Progress log line · dashboard refreshed.

## 11. Stop conditions
Stop and ask if: a required image cannot be pulled, port 5433/1025/8025 is also occupied, or running the stack would require touching the unrelated `medpet-postgres` container.
