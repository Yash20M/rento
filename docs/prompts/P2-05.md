# P2-05 — Meta (Facebook) verifier

## 1. Role
Senior backend/security engineer (NestJS, Graph API, OIDC) on Rento.

## 2. Context
- P2-03 built the social core and `SocialIdentityVerifier` port; P2-04 added Google and the JWKS cache (now shared at `providers/shared/jwks-cache.ts`). This task adds **Meta** with its two token kinds (README §15.1): **Classic Login** access token and **iOS Limited Login** OIDC `AuthenticationToken` + nonce.
- Facts confirmed against Meta (2026-10-15): OIDC discovery at `https://limited.facebook.com/.well-known/openid-configuration/` ⇒ issuer `https://www.facebook.com`, keys at `https://www.facebook.com/.well-known/oauth/openid/jwks/` (`Cache-Control: max-age=60`), RS256, claims include `sub`, `aud`, `exp`, `nonce`, `name`, `email`. Classic: Graph `GET /debug_token?input_token=<user token>&access_token=<APP_ID>|<APP_SECRET>` → `data.{app_id,is_valid,expires_at,user_id,type}`, then `GET /me?fields=id,name,email`.
- NOT verifiable offline (go on the manual checklist, P3-13/P4-12): whether the Limited-Login `nonce` claim is the raw nonce or its hash, and whether the Limited-Login `sub` equals the classic `user_id` for the same person. We compare the raw nonce; if Meta's `sub` differs from the classic id, one person may get two accounts until linked (P2-07).
- Decisions (engineering; flagged): (1) Meta is enabled iff `FACEBOOK_APP_ID` **and** `FACEBOOK_APP_SECRET` are set (both or neither; else 404). (2) **Facebook email is always unverified** (`emailVerified:false`) — README policy. (3) Graph base URL `FACEBOOK_GRAPH_URL` default `https://graph.facebook.com` (versionless ⇒ the app's configured Graph version; pin e.g. `…/v24.0` if wanted); https required in production. `FACEBOOK_JWKS_URL` default as above. (4) Classic requires `type=USER`, `app_id` equal to ours, `is_valid`, `expires_at` 0 or in the future (injected Clock), and `/me.id == debug.user_id`; `/me` is called with `appsecret_proof`. (5) Meta 4xx answers (bad/expired/other-app token) ⇒ invalid token; 5xx/429/timeouts/network ⇒ `503 RETRY_LATER` (not an invalid token). (6) The app secret is never logged or returned; the app token goes in the query string only toward Meta over https, and request URLs are never logged.
- Out of scope: Apple (P2-06), identity endpoints (P2-07), data-deletion callback for Live mode (Phase 4 hardening, README §15.1 ❓), real Meta app (P0-03).

## 3. Goal
`POST /v1/auth/social/facebook` accepts exactly tokens issued to our Meta app (both modes), never treats the Facebook email as verified, tolerates missing email, and separates "invalid token" (401) from "Meta unavailable" (503) — proven against fake Graph and JWKS servers.

## 4. Requirements
1. Classic `{accessToken}`: debug_token then /me as in §2.4; subject = `user_id`; `name` from /me; `email` from /me or null; `emailVerified` always false.
2. Limited `{authenticationToken, nonce}`: `jwtVerify` RS256, issuer `https://www.facebook.com`, audience = app id, `exp`/`nbf` ±10 s, required `sub`,`exp`,`iss`,`aud`,`nonce`; token `nonce` must equal supplied `nonce`; subject = `sub`; `email`/`name` from claims (strings only); email unverified.
3. Rejections ⇒ `SocialTokenInvalidError`: other provider's credentials; empty/oversized (> 4096 classic, > 8192 limited) token or nonce; debug `is_valid=false`; `app_id` of another app; `type` ≠ USER; expired; missing `user_id`; `/me.id` ≠ `user_id`; Meta 4xx; malformed JSON; limited: bad signature, `alg=none`, HS256 key confusion, wrong iss/aud, expired, missing/wrong nonce.
4. Infrastructure failure (5xx, 429, network error, timeout 5 s, unreadable body from a 2xx) ⇒ `RetryLaterError`; limited-mode key fetch trouble follows the shared cache (stale keys, 503 when cold).
5. Config: `FACEBOOK_APP_ID`, `FACEBOOK_APP_SECRET` (together), `FACEBOOK_GRAPH_URL`, `FACEBOOK_JWKS_URL`; messages never echo values; production needs https for both URLs.
6. Wiring in `socialVerifiersProvider`; unset ⇒ 404.
7. Logs never contain tokens, the secret, emails or subjects.

## 5. Test plan (written first)
Unit with a fake Graph server (`FakeGraphServer`: configurable debug/me responses, records requests) and the existing `FakeJwksServer`: M-1 valid classic (fields + proof/secret sent only to Meta, email always unverified); M-2 no email ⇒ null; M-3 other app id; M-4 `is_valid:false`; M-5 expired `expires_at` (Clock) and `expires_at:0` (non-expiring) accepted; M-6 type `PAGE`; M-7 `/me.id` mismatch; M-8 Meta 400 error body; M-9 5xx/429/unreachable/timeout ⇒ RetryLater; M-10 bad JSON; M-11 valid Limited (nonce match, email unverified); M-12 wrong nonce / missing nonce; M-13 forgeries (alg none, HS256 confusion, wrong key, wrong iss/aud, expired); M-14 oversize/empty; M-15 other provider credentials; M-16 logs clean; U-1/U-2 config. API: F-1 end-to-end both modes create user with `email NULL` + `needsProfileCompletion:['email']` even when Facebook returns an email; F-2 Facebook email equal to an existing verified password user ⇒ `409 ACCOUNT_LINK_REQUIRED` (never auto-links); F-3 invalid ⇒ 401; F-4 Meta down ⇒ 503; F-5 unset ⇒ 404. Mutations: trust Facebook email as verified; skip app-id check; skip `is_valid`; skip nonce comparison; 5xx treated as invalid.
