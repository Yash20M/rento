# M29 — Merchandising: offers, new arrivals, banners and a two-column product grid (P3-55, P3-56, P3-57)

**Goal (owner, 2026-10-27):** the customer home shows products two to a row; offers, new arrivals and banners appear on it and are all controlled by the admin — nothing hard-coded. A person should be able to see at a glance what is on offer and what is new, and the price they will actually pay.

## Engineering defaults chosen (business rules not stated by the owner — revisit on request)
- **Offer = a percentage discount on the slot price of an item model**, 1–90 %, optional start and end instant (UTC). Active when `now` is inside the window (open ends allowed). The discount in paise is `floor(price × pct / 100)` — never rounded in the customer's disfavour twice; the effective slot price is `price − discount`. Deposit is never discounted.
- **The price is fixed when the booking is created** (effective price at that moment). The booking stores `price_paise` (what is charged) and `discount_paise` (what the customer saved), so refunds, reports and receipts stay correct if the offer later ends or changes. Extensions use the effective price at extension time.
- **New arrival** = the item model was created within the last **14 days** (constant `NEW_ITEM_DAYS`).
- **Featured** = an admin flag on an item model.
- **Banners** ("promotions"): title, optional subtitle and call-to-action label, one picture, a colour theme, an optional product to open, an optional schedule, an on/off switch and a sort order. Shown to customers only while active and inside their schedule.
- Permissions: reuse `inventory:read` / `inventory:write` (merchandising is catalogue work); no new permission, no role-matrix change. Every admin mutation is audited in the same transaction.

## Scope
- **Database (forward-only, `0019`)**: `item_models.discount_percent / discount_starts_at / discount_ends_at / featured`; `bookings.discount_paise`; table `promotions`.
- **API**: effective price everywhere a price is read or charged (inventory, availability, booking, extension); `GET /v1/drawers/:id/inventory` carries `originalPricePerSlotPaise`, `discountPercent`, `discountEndsAt`, `isNew`, `featured`, `createdAt`; booking shows `discountPaise`; public `GET /v1/promotions`; admin CRUD `…/admin/promotions` + picture upload; item-model create/update accept the offer fields with validation (percent range, end after start, dates need a percent, window sanity). OpenAPI regenerated.
- **Admin panel**: item-model form gets an Offer section and a Featured switch; the table shows the offer price, % badge, "New", "Featured"; new page **Offers & banners** (list with live/scheduled/ended state, create/edit with picture, product picker, theme, schedule, order, on/off, delete).
- **Customer app**: two-column grid (three on tablets, four on desktop); compact product card with price + struck-through original, `−20 %`, `New`, `Available`; home order = banners → "Offers for you" → "New arrivals" → all products; drawer page uses the same grid; product page shows the offer, when it ends, and "You save ₹X" in the price summary, checkout and booking detail. All of it computed from server data.
- **Seed** (demo): a 20 % offer on one product, one featured product, one banner with a real photo.

## Tests (written first)
- unit: pricing (discount maths, window edges, rounding, no discount outside window), offer validation, home-section builder (Dart).
- db: constraints on the new columns (percent range, window order, theme values).
- api: admin CRUD + validation matrix + 401/403/404, audit rows, public lists hide inactive/ended/future banners, effective price in inventory/availability, booking charges the discounted price and stores `discount_paise`, an ended offer does not change an existing booking, extension price.
- admin (vitest): offer fields + messages, table badges, promotions page CRUD, image upload.
- app (flutter): 2-column grid at phone/tablet/desktop, badges, banner carousel, sections order and emptiness, price summary with savings, responsive sweep including the new widgets.
- live UI (Playwright against the real stack): admin sets an offer and creates a banner → the public API shows them.
