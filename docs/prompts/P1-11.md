# P1-11 — `pnpm verify` + CI pipeline

## 1. Role
You are a senior DevOps/release engineer on the Rento monorepo (pnpm workspaces + a Flutter app).

## 2. Context
- Product: Rento platform; quality gates exist per area (P1-01…P1-12): lint/typecheck, API unit/db/api/concurrency suites, contract drift, admin unit + Playwright, Flutter analyze/format/test, DB-types and l10n/freezed codegen.
- Architecture in play: root scripts, `scripts/` (Node, cross-platform), `.github/workflows/ci.yml`, `docs/ci.md`.
- Relevant README/plan sections: plan §5.2 (gate commands; `pnpm verify` = "runs all of the above that apply"), plan §6 (testing conventions: Testcontainers, no retries, concurrency suite is a **required** check), README §16 (CI gates order: lint → unit → DB integration incl. concurrency → API → contract drift → Flutter → build), README §17.1 (GitHub Actions: on PR lint/test/contract-drift), ADR-005 (node-pg-migrate keeps no checksums ⇒ CI must fail if an applied migration is edited or deleted), ADR-010 (contract + Dart guard).
- Existing code to read first: root `package.json`, `apps/*/package.json`, `packages/contracts/scripts/contracts.mjs`, `apps/mobile/pubspec.yaml`, `infra/scripts/check-stack.mjs`.
- Decisions already made (do not revisit): GitHub Actions; Testcontainers uses the runner's Docker (no `services:` DB); Flutter pinned to 3.29.2 (the version used locally); no retries/`continue-on-error`; the repo has **no commits and no remote yet** — the workflow cannot be executed on GitHub from here.
- Out-of-scope neighbours: deploy/CD, container images, staging/prod pipelines (P4-09), mobile store delivery (Fastlane/Codemagic), Flutter `integration_test` (P3-24), the "5 consecutive concurrency runs" CI hardening (P2-29/G-01 — here the suite runs once with its built-in 5 rounds).

## 3. Goal
One command, `pnpm verify`, runs every applicable gate locally and reports a per-step summary; the same gates run in GitHub Actions on every PR and push to `main` with a single aggregate status check; nothing in the pipeline can be skipped or retried silently; editing or deleting an already-applied migration fails CI.

## 4. Scope
**In scope**
- `scripts/verify.mjs` (+ `scripts/verify-steps.mjs`): ordered gate list, flags `--fast` (no Docker/browser), `--only`, `--skip`, `--keep-going`, `--list`, preflight for Docker/Flutter, final summary table, exit code.
- `scripts/check-migrations-immutable.mjs`: git-based immutability guard (ADR-005).
- `scripts/check-generated.mjs`: regenerates generated code (mobile build_runner + gen-l10n) and fails if any committed generated file changes.
- `.github/workflows/ci.yml` with jobs `static`, `api`, `admin`, `mobile`, and an aggregate `ci-success`.
- `docs/ci.md`: how to run locally, what each job runs, required status check, branch protection settings.
- Tests for the scripts and the workflow configuration (`node --test`).
- Root scripts: `check` (lint+typecheck — the old quick `verify`), `verify`, `verify:fast`, `test:scripts`, `check:migrations`, `mobile:codegen:check`.

**Out of scope**: see §2.

## 5. Detailed requirements
1. **`pnpm check`** = `pnpm lint && pnpm typecheck` (fast static gate). **`pnpm verify`** = the full aggregate. `pnpm verify:fast` = `--fast`.
2. **Step list** (id → command; `docker`/`flutter`/`browser` = capability needed), in this order: `lint` `pnpm lint` · `typecheck` `pnpm typecheck` · `scripts` `pnpm test:scripts` · `migrations` `pnpm check:migrations` · `api:unit` · `contracts` (`pnpm contracts:check`) · `contracts:test` (`pnpm --filter @rento/contracts test`) · `admin:unit` · `mobile:format` · `mobile:analyze` · `mobile:test` · `mobile:codegen` (`pnpm mobile:codegen:check`) · then Docker steps `api:db` · `api:http` · `api:concurrency` · then browser step `admin:e2e`.
3. **Behaviour**: stop at the first failing step unless `--keep-going`; steps not run are reported `skipped`; the summary prints id, status (`pass`/`fail`/`skipped`) and duration for every step; exit code 0 only if all selected steps passed; `--list` prints the plan without running; unknown ids in `--only/--skip` are an error (exit 2); `--fast` removes steps that need `docker` or `browser`; a missing required capability (Docker daemon down, `flutter` not on PATH) fails **before** running anything with a message naming the capability and the `--fast`/`--skip` escape hatch.
4. **Migration guard**: `check-migrations-immutable.mjs [--base <ref>]`. For every file under `apps/api/db/migrations/` that exists at the base ref, the working tree must contain it byte-identical after CRLF→LF normalisation; a modified or deleted file ⇒ exit 1 naming the file and the rule; added files are fine; if the base ref does not exist (no commits yet / first push) ⇒ exit 0 with a notice. Default base: `$MIGRATIONS_BASE_REF`, else `origin/main`, else none.
5. **Generated-code guard**: `check-generated.mjs mobile` hashes `apps/mobile/lib/**/*.g.dart`, `*.freezed.dart`, `lib/l10n/generated/*`, runs `dart run build_runner build --delete-conflicting-outputs` and `flutter gen-l10n`, re-hashes, and fails listing changed/added/removed files.
6. **Workflow** (`.github/workflows/ci.yml`): triggers `pull_request` and `push` to `main`; `permissions: contents: read`; `concurrency` group per ref with `cancel-in-progress` for PRs; Node from `.nvmrc`, pnpm from `packageManager`, `--frozen-lockfile`; caches via the setup actions (pnpm store, Flutter/pub); jobs:
   - `static`: checkout with `fetch-depth: 0`, install, `pnpm lint`, `pnpm typecheck`, `pnpm test:scripts`, migration guard with the PR base (`origin/${{ github.base_ref }}`) or the push `before` SHA.
   - `api`: install, `pnpm --filter api test:unit|test:db|test:api|test:concurrency`, `pnpm contracts:check`, `pnpm --filter @rento/contracts test`.
   - `admin`: install, `pnpm --filter admin test`, install Playwright Chromium, `pnpm --filter admin test:e2e`, upload the Playwright report on failure.
   - `mobile`: Flutter **3.29.2**, `flutter pub get`, `pnpm mobile:codegen:check`, `pnpm mobile:format:check`, `pnpm mobile:analyze`, `pnpm mobile:test`.
   - `ci-success`: `needs` every other job, `if: always()`, fails unless every needed job's result is `success` (this is the **one required status check**).
   No job may use `continue-on-error`, retries, `--passWithNoTests`, or skip flags. Third-party actions are pinned to a major version tag.
7. **Docs** (`docs/ci.md`): local usage and flags; job table; "required status check = `ci-success`"; recommended branch protection (require PR, require `ci-success`, require up-to-date branch, no force-push to `main`); the manual one-time repo setup (remote, push) the user must do; known limits (workflow not executed on GitHub from this environment).
