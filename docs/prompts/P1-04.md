# P1-04 — Migration tooling + baseline schema

## 1. Role
You are a senior database/backend engineer (PostgreSQL, PostGIS, SQL-first migrations) on the Rento platform.

## 2. Context
- Product: time-based rental of individually-tracked physical assets from nearby drawers. The single most important guarantee is that two bookings can never overlap on one asset — enforced **by the database** (README §9).
- Architecture in play: `apps/api/db/migrations/*.sql` (schema source of truth, README §4.3, §12.2), a tiny migration runner in `apps/api/src/db/`, real-DB tests.
- Relevant README sections:
  - §4.3 SQL-first decision (tool: `dbmate` or `node-pg-migrate` → record in **ADR-005**).
  - §8.2 Core tables + conventions (UUID PKs, `created_at/updated_at timestamptz`, money in integer paise, enums as `text` + `CHECK`, INR only).
  - §9.1–§9.3 Exclusion constraint on half-open `tstzrange`; expected behaviour table (overlap ⇒ `23P01`, adjacent OK, released row stops blocking).
  - §8.3 Why a single `asset_occupancies` ledger.
- Existing code to read first: `infra/compose.yaml`, `infra/db/init/01-extensions.sql`, `apps/api/package.json`, `apps/api/vitest.config.mts`, `apps/api/src/config/app-config.ts`.
- Decisions already made (do not revisit): forward-only migrations, never edit an applied one; Kysely for queries (P1-05); `READ COMMITTED`; PostGIS `geography(Point,4326)` with `ST_MakePoint(lng, lat)` (longitude first); PostgreSQL 16 + PostGIS 3.4.
- Tool choice (this task decides it): **`node-pg-migrate` v9** — pure Node (no Go binary to install on Windows/CI), plain `.sql` files, programmatic `runner()` reusable by the test fixture, advisory-lock protected, order-checked. `dbmate` rejected: separate native binary.
- Out-of-scope neighbours: Kysely instance + `kysely-codegen` + error mapper + transaction helper + template-DB/factories/Clock → **P1-05**; 50-way concurrency spike → **P1-06**; users' identities/tokens → **P2-01**; roles/permissions → **P2-08/09**; audit/outbox/idempotency/payments tables → their own P2/P4 tasks; least-privilege runtime role → P4.

## 3. Goal
`pnpm --filter api migrate` applies `0001_baseline.sql` to an empty PostGIS database, creating the core tables with the `no_overlapping_occupancy` exclusion constraint and GiST indexes; running it again changes nothing. Database tests (real PostgreSQL+PostGIS in a Testcontainers container) prove the constraint semantics of README §9.3.

## 4. Scope
**In scope**
- `node-pg-migrate` wired as a forward-only runner: `src/db/migrate.ts` (`runMigrations(databaseUrl)`), `src/db/migrate-cli.ts`, script `migrate`.
- Migration `0001_baseline.sql`: extensions (`postgis`, `btree_gist`, `pgcrypto`, `citext`), `set_updated_at()` trigger function, tables `users`, `categories`, `drawers`, `item_models`, `assets`, `bookings`, `asset_occupancies`, constraints and indexes below.
- Minimal Testcontainers bootstrap for DB tests (one PostGIS container per run, a fresh migrated database per test file): `test/support/db/*`, vitest project `db`, script `test:db`.
- Unit test that guards migration file naming/forward-only.
- `docs/adr/ADR-005-sql-first-migrations.md`.

**Out of scope**: see §2 neighbours. No seed data. No Kysely.

## 5. Detailed requirements

### 5.1 Runner
1. `runMigrations(databaseUrl, log?)` calls `node-pg-migrate` `runner({ direction: 'up', dir: <apps/api/db/migrations>, migrationsTable: 'pgmigrations', checkOrder: true, ... })` and returns the list of migrations executed in this call. **No `down` entry point exists** (forward-only).
2. `migrate-cli.ts` reads `DATABASE_URL` through `loadConfig`-style validation (postgres URL), runs `runMigrations`, prints applied names (or "nothing to migrate"), exits 0; on error prints the message **without the connection string** and exits 1.
3. `package.json` scripts: `migrate` (`pnpm build && node --env-file-if-exists=../../.env dist/db/migrate-cli.js`), `test:db` (`vitest run --project db`).
4. Migrations run in a single transaction (all-or-nothing) and under node-pg-migrate's advisory lock.

### 5.2 Migration file rules
5. Files live in `apps/api/db/migrations/`, named `NNNN_snake_case.sql` (4-digit, gapless from `0001`), contain only an up section (`-- Up Migration` marker if the loader needs it) and **no** `-- Down Migration`.

### 5.3 Baseline schema (all `id uuid PRIMARY KEY DEFAULT gen_random_uuid()`; `created_at`/`updated_at timestamptz NOT NULL DEFAULT now()` unless noted; `updated_at` maintained by a `set_updated_at()` BEFORE UPDATE trigger on every table that has it)
6. `users`: `email citext UNIQUE` (nullable), `email_verified_at timestamptz`, `phone text`, `display_name text`, `status text NOT NULL DEFAULT 'active' CHECK IN ('active','suspended','deleted')`.
7. `categories`: `name text NOT NULL`, `slug text NOT NULL UNIQUE`, `parent_id uuid REFERENCES categories(id)`, `CHECK (parent_id IS DISTINCT FROM id)`.
8. `drawers`: `name`, `address` (`text NOT NULL`), `timezone text NOT NULL` (IANA name; validity enforced by the API in P2-17, not by the DB), `location geography(Point,4326) NOT NULL`, `status text NOT NULL DEFAULT 'active' CHECK IN ('active','temporarily_closed','inactive')`, `pickup_instructions text`; GiST index on `location`.
9. `item_models`: `category_id uuid NOT NULL REFERENCES categories`, `name text NOT NULL`, `description text`, `photos jsonb NOT NULL DEFAULT '[]'`, `price_per_slot_paise integer NOT NULL CHECK (>= 0)`, `slot_minutes integer NOT NULL CHECK (> 0)`, `min_duration_min integer NOT NULL CHECK (> 0)`, `max_duration_min integer NOT NULL`, `buffer_min integer NOT NULL DEFAULT 0 CHECK (>= 0)`, `deposit_paise integer NOT NULL DEFAULT 0 CHECK (>= 0)`, `status text NOT NULL DEFAULT 'active' CHECK IN ('active','inactive')`, `CHECK (max_duration_min >= min_duration_min)`. (Slot-multiple rules are API validation, P2-16.)
10. `assets`: `asset_code text NOT NULL UNIQUE`, `item_model_id uuid NOT NULL REFERENCES item_models`, `drawer_id uuid NOT NULL REFERENCES drawers`, `serial_no text`, `status text NOT NULL DEFAULT 'available' CHECK IN ('available','maintenance','in_transfer','retired')`; index `(drawer_id, item_model_id)`.
11. `bookings`: `user_id`, `asset_id`, `drawer_id`, `item_model_id` (all `NOT NULL`, FKs), `status text NOT NULL CHECK IN ('held','confirmed','active','overdue','completed','cancelled','expired','no_show')`, `starts_at`/`ends_at timestamptz NOT NULL`, `buffer_min integer NOT NULL DEFAULT 0 CHECK (>= 0)`, `hold_expires_at timestamptz`, `price_paise integer NOT NULL CHECK (>= 0)`, `deposit_paise integer NOT NULL DEFAULT 0 CHECK (>= 0)`, `currency text NOT NULL DEFAULT 'INR' CHECK (currency = 'INR')`, `pickup_code_hash text`, `cancelled_by uuid REFERENCES users(id)`, `cancel_reason text`, `version integer NOT NULL DEFAULT 1`; constraints `bookings_valid_period CHECK (ends_at > starts_at)` and `bookings_held_has_expiry CHECK (status <> 'held' OR hold_expires_at IS NOT NULL)`; indexes `(user_id, created_at DESC)`, `(asset_id, starts_at)`, `(drawer_id, starts_at)`, and a partial index on `hold_expires_at WHERE status = 'held'`.
12. `asset_occupancies`: `asset_id uuid NOT NULL REFERENCES assets`, `kind text NOT NULL CHECK IN ('booking','maintenance','transfer','admin_block')`, `booking_id uuid REFERENCES bookings(id)`, `during tstzrange NOT NULL`, `released_at timestamptz`, `created_at timestamptz NOT NULL DEFAULT now()`. Constraints, named exactly:
    - `occupancy_bounded CHECK (NOT isempty(during) AND NOT lower_inf(during) AND NOT upper_inf(during))`
    - `occupancy_half_open CHECK (lower_inc(during) AND NOT upper_inc(during))` (enforces `[start, end)` in the DB)
    - `occupancy_booking_link CHECK ((kind = 'booking') = (booking_id IS NOT NULL))`
    - **`no_overlapping_occupancy EXCLUDE USING gist (asset_id WITH =, during WITH &&) WHERE (released_at IS NULL)`**
    - unique partial index `asset_occupancies_one_active_per_booking` on `(booking_id) WHERE booking_id IS NOT NULL AND released_at IS NULL` (a booking holds at most one live occupancy; reassign releases the old row first).
13. All timestamps are UTC instants (`timestamptz`); no `timestamp without time zone` anywhere.

### 5.4 Test database fixture (minimal; P1-05 extends it)
14. A vitest `globalSetup` starts ONE `postgis/postgis:16-3.4` Testcontainers container for the whole `db` project and stops it afterwards. Each test file calls `createTestDatabase()` → `CREATE DATABASE` (random name), runs `runMigrations`, returns `{ pool, url, drop() }`; files never share a database.

## 7. Acceptance criteria
- [ ] AC-1 Fresh database migrates; all baseline tables, 4 extensions and `pgmigrations` row exist. → D-01
- [ ] AC-2 Re-running migrate is a no-op. → D-02
- [ ] AC-3 Overlapping occupancy for one asset ⇒ SQLSTATE `23P01` naming `no_overlapping_occupancy`. → D-03
- [ ] AC-4 Adjacent `[10,11)` + `[11,12)` accepted; same range on different assets accepted. → D-04, D-05
- [ ] AC-5 Releasing a row stops it blocking (and the row remains for history). → D-06
- [ ] AC-6 Empty, unbounded, and non-half-open ranges are rejected (`23514`, named constraints). → D-07
- [ ] AC-7 Booking-link CHECK holds both ways; one live occupancy per booking. → D-08, D-09
- [ ] AC-8 Booking CHECKs (period, held-needs-expiry, status enum, INR, non-negative money). → D-10
- [ ] AC-9 Reference data constraints: unique asset_code, FK integrity, citext-unique email with multiple NULLs, status enums, item_model sanity. → D-11, D-12
- [ ] AC-10 `ST_MakePoint(lng, lat)` round-trips with longitude first. → D-13
- [ ] AC-11 The exclusion constraint is backed by a GiST index covering `(asset_id, during)`. → D-14
- [ ] AC-12 `updated_at` is bumped by UPDATE. → D-15
- [ ] AC-13 Migration files are `NNNN_name.sql`, gapless, forward-only. → U-01
- [ ] AC-14 CLI: `pnpm --filter api migrate` works against the local compose DB; bad URL ⇒ exit 1 without leaking the password. → manual smoke M-01, M-02 (recorded in Evidence)
