# M2 — Catalog & places (fast track: P2-16, P2-17, P2-18, P2-19 (cut), P2-20, P2-21)

Goal: an admin can build the rental catalogue and the places through the API, and a customer can find a drawer, see what it offers and when it is free. Builds on M1 (permissions with drawer scopes, audit log).

Scope decisions (engineering defaults, flagged):
- **Inventory** (`inventory:*`, `assets:*`): categories (tree, slug, delete only when empty), item models (paise integers, slot/min/max/buffer rules; never deleted, deactivate; deactivation blocked by upcoming bookings), assets (unique code, status machine `available ⇄ maintenance`, `→ retired` final, `in_transfer` only by the transfer workflow; leaving `available` blocked by upcoming occupancies; cursor pagination ordered by code; drawer-scoped admins only see their drawers). Photos = https URLs (upload adapter deferred).
- **Drawers** (`drawers:*`): coordinates stored `ST_MakePoint(lng, lat)`; IANA zone validated; weekly hours (one window per day, no overnight — README Q-7 default), closures (`tstzrange`, exclusion constraint), drawer-scoped admins limited to their drawers; creating a drawer needs an unrestricted grant. Service-zone polygons are NOT built (P2-17 trimmed): the demo's service area is the search radius.
- **Discovery (P2-19 cut)**: no settings store/API; env `DISCOVERY_RADIUS_METERS` (5000) and `DISCOVERY_MAX_RESULTS` (3). `POST /v1/drawers/nearby`: active drawers in radius, nearest first, only open-now (hours + closures) and, if a model is given, with a free unit; others are returned separately with a reason. None within the radius ⇒ `422 OUTSIDE_SERVICE_AREA`. Coordinates are never logged or stored.
- **Availability (snapshot)**: `GET /v1/drawers/{id}/inventory`, `GET /v1/drawers/{id}/items/{modelId}/availability?date=` — slot grid in the drawer's local day, per start the number of units that can do at least the minimum duration (buffers, closures, maintenance, running holds applied; expired holds ignored) and the longest possible rental. Responses state `snapshot: true`.
- New error codes: `ALREADY_EXISTS`, `IN_USE`, `HAS_FUTURE_BOOKINGS`.

Tests: API suites per area (permission matrix, validation tables, scoped admin, audit rows, pagination, discovery policy, privacy, availability scenarios with a fake clock), DB constraints for hours/closures, unit tests for time-zone helpers. Mutation checks on the parts that affect money/booking correctness or privacy: expired-hold handling, scope enforcement, closed-drawer suggestion, coordinate logging.
