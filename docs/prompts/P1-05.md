# P1-05 — Typed DB access + test harness

## 1. Role
You are a senior backend engineer (NestJS, PostgreSQL, Kysely) on the Rento platform.

## 2. Context

- Architecture in play: `apps/api/src/db/` (pool, Kysely, transactions, error mapping, generated types), `src/common/clock/`, `DatabaseModule`, and the DB test harness in `apps/api/test/`.
- Relevant README sections:

  - §12.3 — "a `withTransaction(fn)` helper; services never open ad-hoc transactions"; `Clock`, `PaymentProvider`, `NotificationSender` are the deliberate seams.
  - §9.3–§9.4 — `SET LOCAL lock_timeout = '3s'`; `23P01` → 409 `BOOKING_SLOT_TAKEN`; `55P03` → 503 `RETRY_LATER`; READ COMMITTED (no SERIALIZABLE).
  - §15 DB pooling — app pool ≈10 per instance; set `statement_timeout` and `idle_in_transaction_session_timeout`; only transaction-scoped constructs (PgBouncer-safe).
  - Plan §6 Testing conventions — real PostGIS container, clean DB per test file, factories in `apps/api/test/factories`, inject a `Clock`, never `sleep`.
- Existing code to read first: `src/db/migrate.ts`, `src/common/health/*`, `src/app.module.ts`, `src/config/app-config.ts`, `test/support/db/*` (P1-04 minimal fixture + `seed.ts`), `test/db/*.db.spec.ts`.
- Decisions already made (do not revisit): Kysely + `pg`; snake_case in TS (no CamelCasePlugin); READ COMMITTED; money integer paise; UTC `timestamptz`.
- Out-of-scope neighbours: the booking transaction itself and its SAVEPOINT retry loop → P2-22; 50-way concurrency suite → P1-06; idempotency, outbox, audit tables → their P2 tasks; least-privilege runtime role → P4.

## 3. Goal
Application code gets a typed `Kysely<Database>` (types generated from the migrated schema and guarded against drift), a single `withTransaction` entry point that applies `lock_timeout` and translates database failures into domain errors, and an injectable `Clock`. Tests get a fast, isolated, migrated database per file plus factories, a fake clock, and proof the harness really isolates.

## 4. Scope
**In scope**
- Config: `DB_POOL_MAX` (int 1–100, default 10).
- `src/db/`: `generated/database.ts` (kysely-codegen output, committed), `pool.ts` (`createPool`), `kysely.ts` (`createDb`), `errors.ts` (domain DB errors + `mapDbError`), `transaction.ts` (`withTransaction`, `TransactionManager`), `database.module.ts` (global module, tokens `KYSELY`, destroys the pool on shutdown).
- Health `/readyz` ping re-implemented on top of the Kysely pool (replaces the P1-03 stand-alone `pg` pool).
- `src/common/clock/`: `Clock` interface, `SystemClock`, global `ClockModule` (`CLOCK` token).
- Scripts: `db:codegen` (regenerate) and `db:codegen:verify` (fail on drift).
- Test harness: template database migrated once per run, `CREATE DATABASE … TEMPLATE` per file; `createTestDatabase()` returns `{ db (Kysely), pool, url, drop }`; `test/factories/` (replaces `test/support/db/seed.ts`); `test/support/fake-clock.ts`; existing P1-04 db specs ported to factories.

**Out of scope**: see §2.

## 5. Detailed requirements
1. **Pool** (`createPool(config)`): `max = config.dbPoolMax`, `connectionTimeoutMillis = 5000`, session settings `statement_timeout = 15000` ms and `idle_in_transaction_session_timeout = 15000` ms (constants exported for tests), idle-client `error` handler that never crashes the process. Applies per connection (no session-level state beyond these; PgBouncer-transaction-pooling safe).
2. **Kysely** (`createDb(pool)`): `new Kysely<Database>({ dialect: new PostgresDialect({ pool }) })`; `Database` is the generated interface. Column type overrides via codegen: `tstzrange` → `string`, `geography` → `string` (opaque; always read through PostGIS functions).
3. **Codegen**: `pnpm --filter api db:codegen` runs `kysely-codegen --dialect postgres --out-file src/db/generated/database.ts` against `DATABASE_URL` (a migrated DB); `db:codegen:verify` adds `--verify`. The generated file is committed, excluded from ESLint/Prettier, and a db test regenerates it from a freshly migrated container DB and fails if it differs (drift guard).
4. **`withTransaction(db, fn, options?)`**: opens `db.transaction().execute(fn)` at READ COMMITTED; first statement inside sets `lock_timeout` locally via `set_config('lock_timeout', '<ms>ms', true)` (default **3000 ms**, option `lockTimeoutMs`); any thrown error passes through `mapDbError` before propagating; commit on resolve, rollback on throw. `TransactionManager.run(fn, options?)` is the injectable wrapper (same behaviour).
5. **Error mapper** `mapDbError(error): unknown` (pure):
   - `23P01` with constraint `no_overlapping_occupancy` → `SlotTakenError` (extends `AppError`, 409 `BOOKING_SLOT_TAKEN`, detail "The requested slot is no longer available").
   - `23P01` with any other constraint → returned unchanged (never claim "slot taken" for an unrelated constraint).
   - `23505` → `UniqueViolationError` (plain `Error` subclass, NOT an `AppError`; carries `constraint`, `table`) — services translate to a specific code; if uncaught it surfaces as 500.
   - `55P03` and `57014` (statement timeout / cancel) → `RetryLaterError` (extends `AppError`, 503 `RETRY_LATER`, detail "Please retry shortly").
   - anything else (including non-objects) → returned **unchanged (same reference)**.
   - Helper `pgErrorCode(error): string | undefined` exported for savepoint-retry code in P2-22.
6. **Clock**: `interface Clock { now(): Date }`; `SystemClock` returns `new Date()`; Nest provider token `CLOCK` in a `@Global()` `ClockModule`; `FakeClock` (test-only) with `set(date)`, `advance(ms)`, never touches the real time.
7. **DatabaseModule** is `@Global()`, provides `KYSELY` (from `APP_CONFIG`) and the shared `Pool`; `onModuleDestroy` calls `db.destroy()` exactly once (ends the pool). `AppModule.register` imports it and `ClockModule`.
8. **Readiness**: `DATABASE_PING` provider = `KyselyDatabasePing(db)`; `ping()` runs `select 1` and rejects after 2000 ms. `PgDatabasePing` is deleted. P1-03 api tests (A-02b real unreachable DB, A-14 destroy hook) stay green unchanged.
9. **Test fixture**: `global-setup` starts one `postgis/postgis:16-3.4` container, creates database `rento_template`, migrates it with `runMigrations`, provides `dbAdminUrl` + `dbTemplateName`. `createTestDatabase()` = `CREATE DATABASE <random> TEMPLATE rento_template`; `drop()` ends the pool and drops the database. Option `{ migrate: false }` yields an empty database (used by the migration tests).
10. **Factories** (`test/factories/index.ts`): `createFactories(db)` → `user`, `category`, `drawer`, `itemModel`, `asset`, `booking`, `occupancy`; each inserts one valid row, auto-creates missing parents, accepts overrides, returns the inserted row (typed `Selectable`). Deterministic sequences for unique fields (`asset_code`, `slug`, `email`). Plus `range(from, to)` helper producing a `[from,to)` tstzrange literal.
